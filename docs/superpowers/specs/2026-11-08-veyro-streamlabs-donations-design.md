# Veyro: ربط Streamlabs ودونيشن «كريترز» — التصميم

التاريخ: 2026-11-08 · الحالة: موافَق عليها

## الفكرة والسبب

الستريمر يستقبل دعم مادي (دونيشن) عن طريق «كريترز» (دكان تب)، وكريترز
مربوط بحسابه في Streamlabs فيوصل الدعم لـStreamlabs كدونيشن. صاحب المنصة يبي
Veyro يستقبل هالدونيشن من Streamlabs مباشرة ويعرضه على شاشات البث: أليرت
لكل مبلغ، توب الداعمين، هدف، آخر دعم، وصورة الإحصائيات — وكل شي باختيار
الستريمر، و**بدون أخطاء بالأرقام**.

الربط مع Streamlabs يغطي كريترز وأي مصدر ثاني مربوط فيه (PayPal وغيره) —
ما نحتاج ربط مباشر مع كريترز.

## الأهداف

1. الستريمر يربط حسابه في Streamlabs مرة وحدة من Veyro (لصق «Socket API Token»).
2. كل دونيشن يوصل Streamlabs يوصل Veyro ويطلع بشاشات البث خلال ثواني.
3. **الأليرتات:** حدث جديد «دونيشن» بنظام الأليرتات الحالي (بطاقة وفيديو)، ولكل
   أليرت مدى مبلغ (من/إلى بالدولار) — يقدر يحط أليرت مختلف لكل مبلغ.
4. **التوب:** قسم «الدونيشن» بصف «التوب» بكل تصاميم العرش والقائمة (اختياري).
5. **الهدف:** هدف جديد يتعبّى بمجموع الدونيشن بالدولار.
6. **آخر دعم:** أداة تعرض آخر داعم ومبلغه (ورسالته اختياري).
7. **الإحصائيات:** قسم «داعمين الدونيشن» الموجود بصورة الإحصائيات (`veyro/stats-card.js`) يشتغل فعلياً.
8. **دقة:** ما يضيع دونيشن (ينحفظ بالسيرفر)، وما ينحسب مرتين، وسجل يوري الستريمر كل اللي وصل.

## خارج النطاق

- زر «اربط Streamlabs» بتسجيل الدخول (OAuth) — **مرحلة ثانية** بعد تسجيل تطبيق
  عند Streamlabs وموافقتهم. التصميم هنا يخلّي إضافته سهلة (نفس الرمز بالنهاية).
- ربط مباشر مع API كريترز.
- تحويل العملات.
- أحداث Streamlabs الثانية (متابعين تويتش/يوتيوب، اشتراكات…) — الدونيشن بس.

## اللي يعتبر فشل حتى لو "اشتغل"

- دونيشن وصل Streamlabs وما طلع (ضاع) أو طلع مرتين أو انحسب مرتين بالتوب/الهدف.
- رمز Streamlabs السري ينكشف بالواجهة أو برابط الشاشة.
- مبالغ بعملات مختلفة تنجمع مع بعض كأنها دولار.
- تجارب Streamlabs («Test Donation» من لوحتهم) تنحسب كدعم حقيقي.
- السيرفر يثقل (Render 0.5 CPU) أو الألعاب تتأثر.

## القيود

- **Streamlabs Socket API:** اتصال socket.io (نسخة 2) على `https://sockets.streamlabs.com?token=<socket token>`،
  والأحداث تجي باسم `event` بشكل `{ type: 'donation', message: [ { _id|id, name, amount, currency, message, … } ] }`.
  المنفّذ يتأكد من شكل الحدث وحقل التجارب من توثيق Streamlabs قبل البناء.
- يحتاج مكتبة `socket.io-client` (نسخة 2.x المتوافقة مع سيرفرهم) بالسيرفر — أول مكتبة جديدة.
- اتصال واحد مفتوح لكل ستريمر مربوط **طول الوقت** (مو بس وقت البث) — عشان الدعم وقت ما يبث ينحفظ.
- الأسرار: الرمز ينحفظ بالسيرفر مع حساب الستريمر، وما يرجع للواجهة أبداً (نفس مفتاح يوتيوب الخاص).
- صفوف الإعدادات: العنوان يمين والتحكم يسار (CLAUDE.md).
- اللي تغيّر ببيانات الشاشة يمر بنفس طريق الأحداث الحالي (`/api/public/screen/events` كل ثانيتين).

## الطرق اللي نوقشت

| الطريقة | الإيجابيات | السلبيات | القرار |
|---|---|---|---|
| **أ. الستريمر يلصق «Socket API Token»** | يشتغل من اليوم بدون موافقة أحد | خطوة يدوية (نشرحها بالخطوات) | **المختارة الحين** |
| ب. زر «اربط Streamlabs» (OAuth) | أسهل للستريمر | تسجيل تطبيق وموافقة Streamlabs (وقت ومو مضمونة) | **مرحلة ثانية** |
| ج. رابط الشاشة يتصل بـStreamlabs مباشرة | بدون سيرفر | الرمز ينكشف برابط OBS، الدعم والشاشة مسكّرة يضيع، وتكرار مع أكثر من شاشة | مرفوضة |

## التصميم

### ١. السيرفر — `backend/streamlabs/`

**أ) التخزين (SQLite)**
- `streamlabs_links(user_id PK, socket_token, status, last_error, linked_at, last_event_at, counter_from, auto_reset)`
  - `status`: `connecting | connected | error | invalid_token`.
  - `counter_from`: بداية عدّاد الدونيشن (التوب/الهدف/الإحصائيات تحسب من هنا).
  - `auto_reset`: يتصفّر العدّاد تلقائياً مع بداية كل بث جديد (live-session جديدة).
- `donations(id PK, user_id, sl_id, name, amount_cents, currency, message, is_test, received_at)`
  مع **`UNIQUE(user_id, sl_id)`** — نفس الدونيشن ما ينحفظ مرتين أبداً.
  المبلغ بالسنتات (عدد صحيح) — ما فيه أخطاء كسور.

**ب) الاتصال — `streamlabs-connector.js`**
- عند تشغيل السيرفر: يتصل لكل ستريمر مربوط. عند الربط: يتصل فوراً.
- إعادة اتصال تلقائية مع تأخير متزايد. رمز مرفوض ← `invalid_token` ويوقف (ما يعيد بلا نهاية).
- كل حدث `donation` ← لكل عنصر بـ`message[]`: يتحقق، ويحفظ (`INSERT OR IGNORE`)، ولو انحفظ جديد يضيفه
  لطابور الأحداث بالذاكرة (للأليرتات). تجارب Streamlabs تنحفظ بـ`is_test=1`: تطلع أليرت، وما تنحسب.
- عملة غير الدولار: تنحفظ وتطلع أليرت بعملتها، وما تنحسب بالمجاميع (السجل يكتب «عملة مختلفة»).

**ج) البيانات للشاشة**
- `GET /api/public/screen/events` يرجّع زيادة `dseq` و`donations` (الجديد بعد `d=`) — بس لو الشاشة فيها
  أداة تستخدم الدونيشن، وبنفس منطق «أول طلب = نقطة بداية» الحالي.
- الإحصائيات: قسم جديد `donors` بـ`/api/public/screen/stats` (ونفس الشي بـ`/api/stream/session-stats`)
  ← أعلى الداعمين من `counter_from`: `{ name, amount (دولار), count }` مجمّعين بالاسم. والمجموع
  `totals.donations` (دولار) و`totals.lastDonation` (آخر دعم: الاسم والمبلغ والرسالة).

**د) مسارات الحساب (`screensGate`)**
- `GET /api/streamlabs` ← `{ linked, status, lastError, lastEventAt, counterFrom, autoReset }` (بدون الرمز).
- `POST /api/streamlabs/link { token }` ← يتحقق (يتصل فعلاً ويستنى أول رد/رفض بمهلة) ويحفظ.
- `POST /api/streamlabs/unlink` ← يقطع ويمسح الرمز (الدونيشن المحفوظ يبقى).
- `POST /api/streamlabs/reset` ← `counter_from = الحين`. `POST /api/streamlabs/settings { autoReset }`.
- `GET /api/streamlabs/donations?limit=50` ← السجل (آخر الدونيشن مع العملة والتجارب).
- «جرّب دونيشن» من المحرر عبر `screen-tests` بنوع جديد `donation` (مبلغ مثال) — ما ينحفظ.

### ٢. المحرّك المشترك (`js/agp-stream-overlay.js`)

- **الأليرت:** `ALERT_EVENTS_ALL.donation` = `{ label: 'الدونيشن', title: 'دعم جديد', msg: '{name} دعم بـ{amount}' }`،
  ومتغيّرات الرسالة `{amount}` (مثل `$25`) و`{message}`. شرط المبلغ: `minAmount ≤ المبلغ ≤ maxAmount`
  (0 = بدون حد أعلى) — مثل `minDiamonds`. أليرت الفيديو والبطاقة الاثنين.
- **التوب:** `SECTIONS.donors` (العنوان «أعلى الداعمين بالدونيشن»، الرقم `$1,250`، أيقونة دولار ذهبية) —
  يطلع بصف «التوب» (الداعمين/المكبّسين/الدونيشن/…) بكل التصاميم.
- **الهدف:** `METRICS.donations` (`$`) بأداة الهدف (شريط/دائرة/كرة القمر).
- **آخر دعم:** أداة جديدة `lastdonation`: الاسم والمبلغ (والرسالة اختياري)، تتحدّث مع كل دعم جديد.

### ٣. Veyro (`veyro/studio.js`)

- **بطاقة «Streamlabs»** (بقسم «الرابط والإعدادات» + رابط لها من الرئيسية):
  الحالة (متصل/يتصل/خطأ + السبب)، خانة لصق الرمز مع خطوات مصوّرة نصياً
  (Streamlabs ← Settings ← API Settings ← API Tokens ← Socket API Token)، «ربط/فصل»،
  «تصفير عدّاد الدونيشن» + «تصفير تلقائي مع كل بث»، وسجل آخر الدونيشن.
- قسم الأليرتات: «الدونيشن» بأحداث الأليرت مع «من/إلى» بالدولار.
- قسم الأهداف: «هدف الدونيشن». قسم التوب: الدونيشن بصف «التوب». أداة «آخر دعم».
- صورة الإحصائيات: قسم «داعمين الدونيشن» يشيل «يتفعّل بعد ربط Streamlabs» ويقرأ البيانات.

## قرارات صاحب المنصة

- الربط بلصق الرمز (أ) الحين، وزر تسجيل الدخول (ب) بعدين.
- الدونيشن يطلع بالأليرتات والتوب والهدف والإحصائيات وآخر دعم — وكل شي باختيار الستريمر.
- أليرت لكل مبلغ.
- العملة: الدولار.

## قرارات مني (قابلة للتعديل)

- **عدّاد الدونيشن** (للتوب والهدف والإحصائيات) يبدأ من وقت الربط، والستريمر يصفّره متى ما
  بغى، أو يفعّل «تصفير تلقائي مع كل بث جديد». السبب: الدعم يجي حتى وقت ما يبث.
- عملة غير الدولار: أليرت بعملتها، وما تنحسب بالمجاميع.
- تجارب Streamlabs: أليرت بس، ما تنحسب.
- التوب يجمع الدونيشن بالاسم (نفس الشخص أكثر من مرة = مجموعه).
- رسالة الداعم مخفية افتراضياً بأداة «آخر دعم» وبالأليرت (`{message}`) — الستريمر يفعّلها لو يبي، لأن
  الرسالة يكتبها أي أحد وتطلع على البث مباشرة.

## متروك للمنفّذ

- شكل أداة «آخر دعم» وأيقونة الدولار بهوية Veyro.
- مهلة التحقق من الرمز وتأخير إعادة الاتصال.
- الاختبارات: `node:test` للتخزين والتكرار والتجميع والعملات والتصفير، وموصّل وهمي بدل Streamlabs، وفحص بالمتصفح.
- تحديث `docs/CHANGELOG.md` و`docs/BACKEND_ARCHITECTURE.md`.
